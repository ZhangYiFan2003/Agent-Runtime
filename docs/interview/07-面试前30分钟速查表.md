# Axiom 面试前 30 分钟速查表

> 只在最后一轮复习使用。细节回到第 1～6 册，生产场景回到第 8 册。

## 1. 30 秒项目介绍

Axiom 是一个面向本地和企业内部 Coding Agent / Tool 工作流的 Durable Agent Runtime。它把 ReAct、Plan-and-Execute 和 Planner/Worker/Reviewer 统一到可恢复 Run 上，并围绕 Tool 安全、Context、预算、无进展、依赖超时与安全重试、完成验证、Trace 和 Evaluation 做运行治理。当前使用 SQLite 和进程内 Supervisor，重点是长任务正确执行与恢复，不是公共百万 QPS SaaS。

## 2. 90 秒项目介绍

我主要解决三个问题。第一，Agent 长任务如何不因进程退出、Tool 副作用或多 Agent 并发而失控：我用 Run/Checkpoint CAS、ToolExecution 和 durable Child Run 保存状态，用预算和无进展检测约束循环。第二，模型怎样安全获得外部能力：ToolRegistry/Executor 统一本地与 MCP Tool，并在写操作前做 HITL、路径/命令校验和审计。第三，怎样证明效果：代码检索有固定 Recall@5/MRR 数据集，Runtime 有 Trace/Span 和多 trial Evaluation，Badcase 经人审后进入 Regression。

我会主动说明边界：并发调度和 Active Run ownership 目前都在单进程内；SQLite 适合当前本地范围；Guard 不是沙箱；外部写 Tool 不能保证通用 exactly-once；模型输出 final 也不等于完成已验证。

## 3. 五条简历原句

1. 实现 ReAct、Plan-and-Execute 与 Planner / Worker / Reviewer 多 Agent 模式；按 DAG 依赖拆分任务并由 asyncio 调度就绪节点，单批最多并发 4 个只读 Tool，写操作串行执行；在固定 Tool I/O 基准下较串行耗时降低约 74%。

2. 为统一异构工具接入与敏感操作控制，设计 Tool Runtime，通过 ToolRegistry / ToolExecutor 管理文件、Shell、Web 抓取、代码检索及 MCP 工具；基于 MCP SDK 支持 stdio / Streamable HTTP，通过 HITL、路径/命令校验与 JSONL 审计约束敏感操作。

3. 构建 Code Intelligence，基于 tree-sitter AST 分块与 SHA-256 增量索引，融合 FTS5 / BM25 与 Embedding 检索并通过 RRF 排序，结合符号解析与调用关系补充跨文件上下文；建立 lexical / vector / hybrid 固定离线检索集，以 Recall@5 / MRR 做检索回归。

4. 基于 SQLite 持久化 Thread / Turn / Event、Run / Checkpoint 与 ToolExecution，在 LLM / Tool / interrupt 边界保存状态，支持 ReAct Run 进程重启恢复并通过稳定 invocation ID 复用已完成 Tool 结果，结合 Map-Reduce 摘要与 Token Budget 管理长上下文。

5. 构建 Runtime API，支持 Run 创建/查询、interrupt / resume / cancel 与 SSE 事件重放；基于 Trace / Span 记录延迟、TTFT、Token 与 Tool 调用指标，并支持固定任务集回归评测。

## 4. 15 个最高频问题

### 1. 为什么保留三种 Agent 模式？

任务结构不同：短而开放用 ReAct，依赖明确用 Plan/DAG，角色分工用 Multi-Agent。策略不同，但复用同一 Durable Runtime 治理。

### 2. DAG 怎么调度？

只启动所有依赖已完成的就绪节点，并受 Child Run 上限约束；失败依赖的下游跳过、重规划或失败。

### 3. asyncio 为什么能提速？

它在 LLM/Tool 等 I/O 等待时推进其他协程，不会让 CPU 计算自动变快，也不保证下游容量提升。

### 4. 为什么写 Tool 串行？

写操作的顺序和副作用会影响最终状态。只有同时声明只读和并发安全的 Tool 才进入并发批次。

### 5. MCP 与 Function Calling 什么关系？

模型用 Function Calling 表达调用意图，Runtime 用 MCP 发现和调用外部能力，MCP 消息采用 JSON-RPC；三者不是一层。

### 6. Guard 是沙箱吗？

不是。路径/命令规则是应用层拒绝，真正多租户还需容器、最小权限、网络和资源隔离。

### 7. 为什么混合检索？

BM25 抓精确标识符，Embedding 抓语义，Symbol 抓定义；RRF 用名次融合不可比分数，再用调用关系补结构上下文。

### 8. 怎样证明检索提升？

固定 development/holdout，报告 Recall@5、MRR@5、延迟和分类指标；当前确定性向量只证明离线管线，不代表真实语义质量。

### 9. 进程挂了怎样恢复？

加载最新版本化 Checkpoint，重建 Runtime，从待处理边界推进；SUCCEEDED ToolExecution 按稳定 invocation 复用。

### 10. Tool 成功但未落库怎么办？

结果未知。timeout 不等于操作确定失败；读操作或显式幂等操作可做有界重试，普通写操作要幂等键、状态查询或补偿。SQLite 记录不能给外部世界 exactly-once。

### 11. 怎样管理长 Context？

保护协议、目标、近期原文和结构化状态；摘要早期历史、投影超大 Tool 输出；每次 LLM 前重估，hard limit 超限则不调用 provider。质量要分开看协议结构、必需状态保留率、压缩率，以及可确定时的压缩/未压缩任务结果；压得更多不自动代表更好。

### 12. 怎样防 Agent 死循环？

步骤预算做硬上限，ProgressDetector 再识别重复动作、错误、短循环和状态停滞；先给恢复提示，仍无进展则终止。

### 13. cancel 怎么生效？

Supervisor 向本进程 Task 发线程安全取消信号，Durable Runtime 将业务状态收敛并保存；内存信号与持久事实都需要。

### 14. 错误率正常，为什么任务成功率会下降？

模型可能更绕、更贵或答案错误但请求仍 200。要看多 trial 成功率、步骤、Token、cost per success、Badcase 和 Regression。

### 15. 模型说完成，为什么不直接信？

模型 final 只表示终止提议。配置了 Completion Contract 时，Runtime 用 ToolExecution、Plan/Child state、输出和 workspace 产物等确定性证据验证；无契约的开放任务是 `NOT_APPLICABLE`，不能冒充客观验证，也没有通用语义 Judge。

### 冻结后必须说准的 6 个区分

1. Timeout 限制一次 attempt；deadline 限制整个 Run 剩余 lifetime。
2. Tool timeout 表示结果可能未知，不表示远端副作用一定没发生。
3. 普通写 Tool 超时不盲目重试；稳定 invocation ID 也不能代替服务端幂等。
4. 实际模型/Tool retry attempt 继续消耗正常调用与 wall/token/cost Budget。
5. 模型提出 final 不等于配置的 Completion Contract 已通过。
6. Compression ratio 只描述缩小多少，不代表 required state 和推理质量保留多少。

## 5. 10 个必须主动声明的边界

1. 当前是本地/企业内部 Runtime，不是公共高 QPS SaaS。
2. ActiveRunSupervisor 与两个 Local Scheduler 都是进程内能力。
3. Checkpoint CAS 防旧写，不提供分布式 ownership。
4. SQLite 适合当前范围，多实例共享要重新设计存储与租约。
5. ToolExecution 能复用已成功结果，不保证所有外部写 exactly-once。
6. PathGuard、CommandGuard、HITL 不是操作系统沙箱。
7. 简化 MCP server 不代表完整覆盖协议；rich content 当前会文本化。
8. 静态调用图是启发式近似，不是编译器级真相。
9. 确定性离线 embedding 不代表生产语义质量。
10. Context 结构测试、模型 final 和基础设施错误率都不能单独证明任务完成质量。

## 7. 10 组可验证数字与条件

1. Tool 固定基准：4 个 Tool，每个模拟等待 0.2 秒。
2. 基准运行：5 次预热，30 次正式运行。
3. 串行平均：828.203ms；4 并发平均：207.773ms。
4. 固定 ToolExecutor 路径改善：74.99%；简历保守写“约 74%”。
5. 串行 P95：845.579ms；4 并发 P95：214.937ms。
6. Retrieval development：40 queries，只用于开发/选权。
7. Retrieval holdout：20 queries，用于留出验证。
8. holdout hybrid_v2：Recall@5 0.8500，MRR@5 0.7667。
9. development hybrid_v2：Recall@5 0.7750，MRR@5 0.7250。
10. 80-query 版本对比工件：hybrid Recall@5 从 0.5125 到 0.7625，MRR@5 从 0.4646 到 0.6858；真实 embedding benchmark 未执行。

这些都是仓库内固定实验，不是生产 SLA、线上 QPS 或真实用户成功率。

## 8. 当前与未来一句话切换

当面试官问多机、1000 用户或生产化时，用这句过渡：

> 当前 Axiom 已经把 Run 状态机、Checkpoint/CAS、Context、Budget、Progress、Trace 和 Eval 做成可复用语义；如果变成共享服务，我会新增准入队列、共享 PostgreSQL、Run 租约/心跳、Worker 池、租户隔离和全局模型配额，而不会假装这些今天已经存在。

## 9. 最后 5 分钟

只背五句话：

1. 我做的是长时间 Agent 执行治理，不是把一个聊天接口包装成微服务。
2. 并发必须受依赖、读写副作用和容量上限约束。
3. durable 的关键是保存边界、CAS 和 Tool 副作用语义，不是“用了 SQLite”。
4. 质量必须同时看任务成功、步骤、Token、延迟与每次成功成本。
5. 任何数字都带数据集、环境、范围和未覆盖项一起说。

最后三个禁句：

- “异步就是多核并行。”
- “有 Checkpoint 就是 exactly-once。”
- “模型说完成，所以任务完成。”
