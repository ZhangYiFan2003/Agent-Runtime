# Axiom 最新源码速通地图

> 目标：面试前能从入口一路讲到状态、工具、观测和评测。所有锚点以当前源码为准；旧归档只作历史参考。

## 1. 先建立仓库全景

```text
src/axiom/
├─ entrypoints/       CLI、REPL 与命令注册
├─ agent/             QueryEngine、轻量 ReAct facade、Plan/Multi-Agent facade
├─ runtime/           Durable Runtime、策略、Checkpoint、预算、进展、API、Supervisor、观测
├─ tools/             Tool 抽象、Registry、Executor、内置工具
├─ mcp/               MCP 配置、客户端、简化服务端
├─ policy/            权限、HITL、路径/命令保护、审计
├─ context.py         ContextBuilder 语义组装 + ContextBudget 窗口约束
├─ memory/            类型化记忆、摘要、事实和记忆上下文
├─ rag/               AST 索引、混合检索、符号/调用图、代码 Context
├─ evaluation/        数据集、Runner、Scorer、Badcase、对比与归因
├─ llm/               LLM 协议、OpenAI-compatible streaming client
└─ plan/              Plan/Task 数据与规划辅助
```

先记住两个世界：`src/axiom/agent/query.py` 是轻量 ReAct 循环，适合 CLI 基础路径；`src/axiom/runtime/durable.py` 是有 Checkpoint、ToolExecution、Budget、Progress 和 Trace 的 durable 路径。它们共享 LLM、Tool 和部分上下文能力，但不能把 durable 路径的全部保证自动套到轻量路径。

## 2. Durable Execution source walk

```text
API request
  ↓ runtime/api.py: RuntimeApiServer
Run creation/control
  ↓ runtime/durable.py: DurableAgentRuntime.start/resume
Checkpoint claim / state reconstruction
  ↓ runtime/storage.py: DurableStorage backend bundle
  ↓ runtime/checkpoints.py / postgres.py: SQLite or PostgreSQL RuntimeStore
Tool logical identity and durable result
  ↓ runtime/models.py: ToolExecutionRecord
Tool policy and physical attempt
  ↓ tools/executor.py + execution/backends.py
Retry / effective timeout / Run deadline
  ↓ runtime/dependency.py + runtime/budget.py
Checkpoint advance with sequence CAS
  ↓ runtime/durable.py:_save_checkpoint
Trace / stored Event replay
  ↓ observability_store.py + runtime/events.py:EventRepository
```

| Step | 源码锚点 | 它负责什么 | 它不负责什么 |
| --- | --- | --- | --- |
| API request | `runtime/api.py:RuntimeApiServer._execute_control_operation` | 幂等控制记录、合法转换、409 conflict | 不拥有跨进程 Worker |
| Run | `runtime/durable.py:start/resume/cancel` | 构造/加载 Checkpoint，驱动策略 | 不恢复旧协程栈 |
| Checkpoint / ownership | `runtime/checkpoints.py`、`runtime/postgres.py:PostgresRuntimeStore`、`runtime/ownership.py` | SQLite 在 `BEGIN IMMEDIATE` 比较 sequence；PostgreSQL 将 sequence CAS 与 owner/fencing 校验组合，并提供 runnable claim、lease renew、过期 takeover 与 Worker loop | 不撤回已发出的外部 Tool 调用 |
| ToolExecution | `runtime/durable.py:_execute_pending_tool_inner` | `run_id:tool_call_id`、参数哈希、成功复用、attempt、显式 retry state、UTC backoff deadline | 不保证外部 exactly-once；unsafe `UNKNOWN` 跨重启仍禁止自动执行 |
| ToolExecutor | `tools/executor.py:execute_one` | schema、permission/HITL、统一结果 | 不是 OS sandbox |
| Retry/deadline | `runtime/dependency.py`、`runtime/budget.py` | 分类、安全性、backoff、剩余 Run lifetime | 不把 timeout 证明成失败 |
| Checkpoint advance | `runtime/durable.py:_apply_tool_result/_save_checkpoint` | 把结果写回消息/策略并 CAS 保存 | 不等于 Event Log |
| Trace/Event | `runtime/observability_store.py`、`runtime/events.py`、`runtime/postgres.py` | 调用链证据、单调但可有 gap 的 Event ID、SSE stored replay | 不参与恢复状态机权威决策 |

最短阅读顺序：`start/resume` → `_execute_llm_step` → `_execute_pending_tool_inner` → `_apply_tool_result` → `_save_checkpoint` → `RuntimeStore.save`。再对照 `SQLiteCheckpointStore` 与 `PostgresRuntimeStore`，看 `test_durable_storage.py` 的共享 contract、CAS 和 retry parity；最后看 `test_durable_runtime.py` 的 success gap/ambiguous window 与 `test_runtime_api_hardening.py` 的 resume-cancel race。

父子取消再看 `DurableAgentRuntime.reconcile_run_control_state`：Parent 先持久化 `CANCELLED`，传播前 crash 时，Child 的显式 resume/执行 preflight 检查 durable ancestors 并收敛为 `CANCELLED`；这不是自动 Recovery Scanner。

## 4. 三条最重要的源码故事

### 故事 A：Durable Execution

一句话：昂贵、有副作用的 Agent 步骤不能只存在于 Python 调用栈。

从 `RunState` 看 Run 的版本化 durable state（`Checkpoint` 是兼容名称），从 `steps.py` 看 ephemeral `StepContext/StepResult/NextAction` 与纯 `CompletionPolicy`，从 `storage.py` 看 backend 选择，从 SQLite/PostgreSQL RuntimeStore 看 CAS，从 `ownership.py` 看 Worker claim/heartbeat/fail-closed，从 `DurableAgentRuntime` 看 ReAct 如何把现有一次 LLM 或 Tool 迭代映射成 StepResult。Thread 管会话；Event 管历史；ToolExecution 管外部调用事实；Step 和 completion decision 都不持久化；Turn 只剩 API/Event 关联兼容。最后用 `test_completion_policy.py`、`test_step_execution_contract.py`、`test_runtime_domain_model.py`、`test_durable_storage.py`、`test_distributed_ownership.py` 与 `test_durable_runtime.py` 看这些边界。

要主动说边界：SUCCEEDED Tool 可以复用；外部写已经成功但本地未落库仍有不确定性；CAS 防旧写，不等于多 Worker ownership。

### 故事 B：Execution Harness

一句话：策略可以变化，但工具、安全、上下文、预算和观测应该复用同一个 Runtime harness。模型调用前由 ContextBuilder 决定“要什么”，ContextBudget 决定“怎么放进窗口”；临时构建结果不持久化。

先读 `RuntimeExecutionStrategy`，再看 `DurableAgentRuntime._run_step_loop()` 如何统一 control/ancestor、ownership 与 wall-budget preflight、StepContext 构造、StepResult 校验和 NextAction 停止规则。ReAct/Plan/Multi-Agent 只向它提供一次策略迭代；Plan 的 `LocalPlanTaskScheduler` 和 Multi-Agent 的 `LocalChildRunScheduler` 仍将独立工作变成 durable Child Run，plan/replan/reviewer 语义没有进入 Runtime。`ToolExecutor` 继续按只读/写入语义调度。

要主动说边界：这仍是单进程、本地 scheduler；`asyncio` 解决 I/O 等待，并不等于分布式或 CPU 并行。

### 故事 C：Quality Loop

一句话：模型能返回答案，不代表系统能证明答案质量。

从 `RunTracer` 看运行证据，从 `DurableEvaluationExecutor` 看评测必须走真实 Runtime，从 `Scorer` 看确定性判断，从 `BadCaseCollector` 看失败如何分类、人审和晋升，再从 `evaluate_regression_gate()` 看 baseline/candidate 门禁。

要主动说边界：result schema 当前是 v4；`StepView` 是从 Trace/ToolExecution 重建的只读投影，不是 Step 持久化；`trial_success_rate` 不是 Pass@k；fingerprint 不证明因果；现有 `CompletionVerifier` 只验证显式的确定性契约，不是 universal semantic judge。

## 5. 关键数据模型一页记忆

### Checkpoint

保存 Run ID、父子关系、状态、版本、消息、pending Tool、策略状态、interrupt/error、预算与进展相关状态。它是恢复事实，不是展示日志。

### ToolExecutionRecord

保存 invocation ID、Run/Tool call、Tool 名称、参数哈希、执行状态、attempt、结果或错误，以及失败分类、error code、`NONE/RETRY_PENDING/RETRY_SUPPRESSED/RETRY_EXHAUSTED`、suppression reason、UTC `next_retry_at` 和累计 backoff。旧 SQLite 表通过 additive `ALTER TABLE` 迁移；缺少旧 retry metadata 的失败/未知记录按安全停止处理。

### Trace / Span / RunMetrics

Trace 对应整次 Run，Span 对应 LLM/Tool/Plan/Worker 等阶段。LLM Span 有 TTFT，RunMetrics 聚合 Token、步骤、逻辑 Tool Span、成本、checkpoint、重试和完成验证证据；物理 Tool attempt 需看 `ToolExecution.attempt`/budget 属性，不能和逻辑调用数混为一谈。

### EvaluationSuiteResult

当前结果 schema v4。保存 case/trial 结果、严格 case pass、直接 trial success、平均延迟/Token/步骤、成本、每次成功成本，以及从现有证据重建的 StepView/Run quality；继续接受 v1/v2/v3。

## 6. 状态与所有权不要混淆

`RunStatus` 当前包含 `RUNNING`、`INTERRUPTED`、`WAITING_APPROVAL`、`WAITING_CHILD`、`COMPLETED`、`FAILED`、`CANCELLED`。状态说明业务执行进度；`ActiveRunSupervisor` 说明本进程当前拥有哪个 asyncio Task。进程重启后状态仍在，Supervisor registry 不在。

PostgreSQL `runs` 已保存 `runnable`、`owner_worker_id`、`lease_until` 与单调 `fencing_token`；`claim_next` 用短事务和 `SKIP LOCKED` 选候选，heartbeat 用数据库时间续租，过期 Run 可被更高 fence 接管。不能把 sequence CAS、ToolExecution 唯一约束或 Supervisor 与 ownership 混为一谈；fencing 也不保证外部副作用 exactly-once。

## 7. Context 与 Memory 的两条路径

### Runtime Context

`src/axiom/context.py` 在每次模型调用前估算并投影消息：保护固定协议、当前目标、recent raw、结构化 summary 与 Tool 配对，必要时压缩，hard limit 超限则在 provider 调用前失败。

质量证据不只看压缩率：`evaluation/context_retention.py` 用固定 10-case 数据集统计 required-state retention、protocol integrity 和 estimated-token compression；它证明固定合成集上的可重复保留，不证明开放语义等价。

### Typed/Conversation Memory

`src/axiom/memory/` 保存事实、偏好、对话摘要和 Tool result digest，并在新 Turn 构造有界记忆上下文。它服务跨回合复用，不承担 pending Tool 或策略恢复。

## 8. Code Intelligence 查询链

`CodeIndex.update()` 做文件发现、SHA-256 判断、解析分块、持久化、embedding 同步和符号解析。`CodeIndex.search()` 路由 lexical/vector/symbol/hybrid；hybrid_v2 从多源取候选并 RRF 融合。`build_code_context()` 再补结构关系并按预算裁剪。

读结果时同时看 `benchmarks/retrieval/results/retrieval-v2-development.md` 与 `retrieval-v2-holdout.md`。记住确定性向量只是可复现管线证据，真实 embedding benchmark 没有执行。

## 9. Runtime API 路由心智图

不用死背 URL，先背职责：

- Thread 创建/查询与事件列表。
- Turn/Run 创建，选择 durable strategy。
- Run/Child Run 查询和 lineage。
- interrupt/resume/cancel 控制操作。
- SSE 读取持久事件，支持 `after_id` 与 Run filter。
- `/health` 检查进程和本地数据库基本状态。

API 的 `_run_turn()`、`_resume_run()`、`_execute_control_operation()`、`_run_view()`、`_recover_waiting_parents()` 是最值得看的路径。

## 13. 最容易混淆的 12 件事

1. 轻量 `agent/query.py` 不等于 Durable Runtime。
2. Thread 管会话；Run 是执行实体；Event 是历史；Checkpoint 是版本化 Run state 机制；Turn 不是恢复 authority。
3. Checkpoint CAS 不等于分布式 Run ownership。
4. ActiveRunSupervisor 是进程本地 registry，不是 scheduler cluster。
5. Child Run 语义不等于普通 asyncio Task。
6. asyncio 并发不等于 CPU 多核并行。
7. MCP 不等于 Function Calling，也不等于 JSON-RPC 本身。
8. PathGuard/CommandGuard 不等于沙箱。
9. tree-sitter 语法树不等于精确类型/调用语义。
10. SHA-256 文件增量不等于 parser incremental parsing 或单 chunk 重算。
11. `trial_success_rate` 不等于 Pass@k。
12. 模型输出 final 不等于客观完成验证。

再补两个冻结后必须讲准的边界：dependency timeout 是单次 attempt 上限，Run deadline 是外层绝对边界；unsafe write timeout 表示外部结果可能未知，不能因为“报错了”就自动重试。

## 14. 用测试作为可执行证据

面试里不要只说“代码里有”。可以这样组织：源码定义能力，测试验证边界，benchmark/评测验证可重复结果。

- Durable：崩溃、恢复、CAS、Tool 重放。
- Concurrency：Child Run 与只读 Tool 上限、写串行。
- Context：协议配对、hard limit 前不调用 provider。
- Budget：并发预留、实际核销、Child 聚合、未知价格。
- Progress：重复动作、错误、短循环、恢复后终止。
- Dependency：timeout/deadline clamp、失败分类、安全重试、指数退避与 full jitter、durable attempt allowance。
- Completion：Verifier/Progress/Budget 提供证据，CompletionPolicy 统一生成通用 NextAction；控制状态优先，ReAct 纠正仍消耗普通 Budget。
- Context Retention：固定 required state、协议完整性、压缩率和可选 full/compressed outcome 对比。
- API/Supervisor：幂等控制、线程安全取消、shutdown。
- Eval：独立 trials、Badcase 审核、schema 兼容、回归门禁。

## 15. 一句话源码定位法

- “任务怎么跑？”→ `runtime/strategies.py`。
- “状态怎么续？”→ `runtime/durable.py` + `runtime/checkpoints.py`。
- “工具怎么管？”→ `tools/registry.py` + `tools/executor.py`。
- “上下文怎么缩？”→ 根目录 `context.py`。
- “成本怎么封顶？”→ `runtime/budget.py`。
- “死循环怎么停？”→ `runtime/progress.py`。
- “依赖超时怎么处理？”→ `runtime/dependency.py` + `runtime/durable.py`。
- “模型说完成可信吗？”→ `runtime/completion.py`（验证证据）+ `runtime/steps.py`（CompletionPolicy 决策）。
- “谁在当前进程运行？”→ `runtime/supervisor.py`。
- “为什么慢？”→ `runtime/observability*.py`。
- “效果有没有回归？”→ `evaluation/*`，上下文保留专项看 `evaluation/context_retention.py`。
- “代码怎么找？”→ `rag/code_index.py`。

## 16. 最后校验清单

讲任何源码能力前都问自己：入口在哪里？状态保存在哪里？失败时怎样？哪个测试能证明？是当前实现、部分支持还是未来设计？只要这五个问题能答清，源码面通常不会变成背文件名。
